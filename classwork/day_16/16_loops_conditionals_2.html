Handling Errors: try / except

A Different Kind of Branching

  • Back in week 3, running print(my_age) before defining my_age gave us a NameError. Python crashed the whole program at that line.
  • if / elif / else branch on whether something is true.
  • try / except branch on whether something causes an error — and let your program keep running instead of crashing.

try / except

try:
    print(my_age)
except NameError:
    print("That variable doesn't exist yet!")
  • Python attempts everything inside try:.
  • If it hits an error, it jumps to except: instead of crashing — and the rest of your program keeps going.

Why Do Linguists Need This?

  • You’ll hit this constantly once you start reading real files (like next week’s Detective Gutenberg activity): wrong filenames, weird encodings, missing data.
  • Instead of your whole script dying on file 47 of 50, try/except lets you catch the problem, note it, and move on.
try:
    with open("mystery_novel.txt", encoding="utf-8") as f:
        text = f.read()
except FileNotFoundError:
    print("Couldn't find that file — check the filename and location.")

Reading an Error Message

  • Before you reach for try/except, get comfortable reading the error itself — Python usually tells you exactly what went wrong, on the last line:
    • NameError → you used a variable that doesn’t exist yet.
    • FileNotFoundError → the file path is wrong.
    • TypeError → you mixed incompatible types (like "5" + 5).
  • Read bottom to top. The last line is the actual error; everything above it is just how you got there.

if Statements vs. for Loops

  • if statements are used to control which pieces of code are run, depending on certain conditions
  • for loops are used to run the same block of code over and over again on items in an iterable.

Back to Brontë

    print(title)
  • What is this code saying?

Back to Brontë

for book in charlotte: 
    print(book)
  • title, book are temporary (loop) variables

Temporary Variables

  • The very last value of the loop variable (book, title, etc.) persists after the loop is finished:
charlotte = ['The Professor', 'Jane Eyre', 'Shirley', 'Villette']
for title in charlotte: 
    print(title)
print(title)

two_line

Building New Lists

Cleaning Every Line?

  • We now know how to clean one line.
  • A for loop lets us clean every line:
for line in book_lines[100:105]:
    print(line.strip().lower())
  • But print() just displays the result – it doesn’t save it anywhere.
  • How do we end up with a new list of cleaned lines?

.append()

  • .append() adds an item to the end of a list:
terms = ["phoneme", "morpheme"]
terms.append("lexeme")
print(terms)
  • So we can start with an empty list and fill it up inside a loop.

Building a List with a Loop

messy = [" Phoneme\n", "MORPHEME ", "  syntax", "Semantics\n"]

clean = []                            # 1. start with an empty list
for term in messy:                    # 2. go through each item
    clean.append(term.strip().lower())   # 3. add the cleaned version

print(clean)
  • What does clean look like? How about messy?

List Comprehensions

  • This pattern (empty list → loop → append) is so common that Python has a shortcut: the list comprehension
clean = [term.strip().lower() for term in messy]
  • Same result, one line, no .append().

Reading a List Comprehension

clean = [term.strip().lower() for term in messy]
  • Read it from the middle out:
    • for term in messy → go through each item in messy, calling it term
    • term.strip().lower() → what to do to each term
    • [ ... ] → collect all the results into a new list
  • General template: [ do something to item for item in some_list]

Loop vs. Comprehension

clean = []
for term in messy:
    clean.append(term.strip().lower())
clean = [term.strip().lower() for term in messy]
  • Same three parts: the source list, the loop variable, and what to do to each item.
